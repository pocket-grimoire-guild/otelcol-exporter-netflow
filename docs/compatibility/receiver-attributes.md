# Canonical receiver-compatible log contract

Status: versioned receiver contract (2026-09-02).

The initial profile is **`contrib-netflowreceiver-v0.160.0`**.  It is defined
by Collector Contrib `v0.160.0` at commit
[`982f20b8a8e8a2569fab3e27cf8b008e8a5080c1`](https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/982f20b8a8e8a2569fab3e27cf8b008e8a5080c1/receiver/netflowreceiver)
and its resolved goflow2/v2 `v2.2.6` dependency at commit
[`c9824f41bcad11d4490a668ed5270b03056d8217`](https://github.com/netsampler/goflow2/tree/c9824f41bcad11d4490a668ed5270b03056d8217).
The pinned receiver parser and populated/empty tests are normative; the
README is descriptive evidence only.  `P` below means `parser.go`, `T` the
[populated](https://github.com/open-telemetry/opentelemetry-collector-contrib/blob/982f20b8a8e8a2569fab3e27cf8b008e8a5080c1/receiver/netflowreceiver/parser_test.go#L41-L142)
and [empty](https://github.com/open-telemetry/opentelemetry-collector-contrib/blob/982f20b8a8e8a2569fab3e27cf8b008e8a5080c1/receiver/netflowreceiver/parser_test.go#L144-L198)
parser tests, `W` the log producer wrapper, `F` goflow2 `pb/flow.proto`,
and `N5`, `N9`, and `S` the pinned [v5](https://github.com/netsampler/goflow2/blob/c9824f41bcad11d4490a668ed5270b03056d8217/producer/proto/producer_nflegacy.go#L11-L64),
[v9/IPFIX conversion](https://github.com/netsampler/goflow2/blob/c9824f41bcad11d4490a668ed5270b03056d8217/producer/proto/producer_nf.go#L284-L655)
and [processing/enrichment](https://github.com/netsampler/goflow2/blob/c9824f41bcad11d4490a668ed5270b03056d8217/producer/proto/producer_nf.go#L747-L830),
and [sFlow](https://github.com/netsampler/goflow2/blob/c9824f41bcad11d4490a668ed5270b03056d8217/producer/proto/producer_sf.go#L44-L119)
producer code.

The parser writes exactly **41** canonical attributes.  `Int` means an OTel
`int64` (`PutInt`), even where the upstream protobuf member is unsigned.  A
project normalizer MUST reject negative values and unsigned values that do not
fit `int64`; it MUST NOT wrap, truncate, clamp, or silently change units.  The
`R` policy means the key is required to be present in parsed-mode input (the
receiver emits it even when its value is a default); `O` means the key may be
absent.  Required does not make a protocol-inapplicable zero meaningful.

## Timing values and original-field provenance

The pinned receiver preserves the start/end values produced by GoFlow2 in
`flow.start` and `flow.end`, and copies start to the log `Timestamp`.
For v9 and IPFIX, GoFlow2 initializes **each endpoint independently** to the
incoming packet's export Unix seconds, converted to nanoseconds, before applying
supported timing fields
([pinned conversion](https://github.com/netsampler/goflow2/blob/c9824f41bcad11d4490a668ed5270b03056d8217/producer/proto/producer_nf.go#L284)).
Thus a start-only record retains a decoded start and an export-time end.
V5 always has fixed First/Last slots: zero is a numeric uptime value that maps
to the header-derived origin, not an absent slot. Its absolute conversion also
includes the input header's residual nanoseconds.

These projected values remain authoritative for the exporter. The receiver
schema exposes neither original timing-IE identity/presence nor the original
packet export timestamp. Equality with export time or a zero duration cannot
identify fallback or prove that a source measured an endpoint. Receiver ingest
is separate: `flow.time_received` and `ObservedTimestamp` carry collection time.
Removing a required timing attribute still rejects the record even if its log
envelope retains a timestamp; no new fallback or provenance inference is added.

GoFlow2 v2.2.6's shared NTP conversion consumes the low 11 fraction bits of
IPFIX dateTimeMicroseconds (IEs 154/155), although
[RFC 7011 §6.1.9](https://www.rfc-editor.org/rfc/rfc7011.html#section-6.1.9)
requires receivers to ignore them.
The [MVP acceptance record](../mvp-acceptance.md) records the paired flow-time
characterization and the separate era/rollover limits. This is
an upstream conversion limit: the exporter preserves the projected value and
cannot safely mask canonical nanoseconds after the source IE identity is lost.

The retained [receiver-first tests](../../integration/receiver/flow_time_test.go)
inspect genuine intermediate attributes and the selected input timing IEs;
the [tagged TShark companion](../../integration/receiver/flow_time_tshark_test.go)
independently decodes received exporter payloads. These supplement the existing
[OCB receiver-first profile tests](../../integration/ocb/operator_example_linux_test.go),
which already establish actual-Collector timing behavior for their finite cases.

## Parsed versus `send_raw`

`send_raw: true` is not datagram passthrough.  The pinned [README](https://github.com/open-telemetry/opentelemetry-collector-contrib/blob/982f20b8a8e8a2569fab3e27cf8b008e8a5080c1/receiver/netflowreceiver/README.md#L83-L87) says it “skips
parsing” and sends a raw message, but the pinned implementation first invokes
the goflow2 producer and then stores `fmt.Sprintf("%+v", msg)` in each log
body ([`producer.go#L35-L60`](https://github.com/open-telemetry/opentelemetry-collector-contrib/blob/982f20b8a8e8a2569fab3e27cf8b008e8a5080c1/receiver/netflowreceiver/producer.go#L35-L60)); the raw test checks that exact formatted `ProtoProducerMessage`
string ([`producer_test.go#L132-L150`](https://github.com/open-telemetry/opentelemetry-collector-contrib/blob/982f20b8a8e8a2569fab3e27cf8b008e8a5080c1/receiver/netflowreceiver/producer_test.go#L132-L150)).  Raw records therefore have no parsed attributes or record timestamps, but retain the same scope metadata.  Formatted raw bodies are rejected as unsupported initial exporter input; replay belongs to a separate design.

## Unknown, custom, and unsupported data

The protobuf contains additional fields (BGP communities, AS path, MPLS, layer
stack, and routing headers) beyond the 41 keys ([`F85-121`](https://github.com/netsampler/goflow2/blob/c9824f41bcad11d4490a668ed5270b03056d8217/pb/flow.proto#L85-L121)).  goflow2 custom mapping can target known protobuf fields or protobuf unknown fields ([`reflect.go#L111-L124`](https://github.com/netsampler/goflow2/blob/c9824f41bcad11d4490a668ed5270b03056d8217/producer/proto/reflect.go#L111-L124)); the receiver parser does not emit those fields as OTel attributes. Extra protobuf fields are absent from this profile. Preservation or mapping of unknown OTel attributes is outside this profile. No automatic name guessing, duplicate-field merge, or unbounded attribute copying is part of this profile. Unknown protocol numbers and flow types remain the literal `unknown` tokens described above.

## Version and upgrade policy

* This profile name is immutable: `contrib-netflowreceiver-v0.160.0` means the
  exact Contrib and goflow2 commits at the top of this document.
* A receiver/dependency upgrade requires an explicit schema diff (names, OTel
  types, source widths, units, presence, and sentinels) plus populated, empty,
  raw, and unknown/custom fixtures before a new profile is accepted.
* Runtime auto-detection is impossible: records carry no receiver schema
  version.  `flow.type` identifies the input protocol only, and scope/resource
  provenance cannot prove the dependency revision.
* Canonical attributes are authoritative over duplicate record timestamps;
  there is no timestamp/body fallback, implicit conversion, truncation, or
  silent coercion.  Missing required keys and invalid placeholders are rejected
  by the exporter normalizer.
